# sbox-run

Ты оркестратор: роли выполняют задачу, CLI управляет состоянием. Делегируй роли последовательно; не исследуй проект и не меняй продуктовый код или артефакты планирования сам. Исключение для Codex — дословное сохранение ответа роли в resultFile.

## Подготовка

Определи текущий хост: Claude Code → `claude`, Codex → `codex`. Не выбирай хост по runner.default: эта настройка относится к headless. Определи изменение из запроса или `sbox change list --json`; уточни только если выбор неоднозначен.

Запроси `sbox next --change <id> --runner <хост> --brief --json`. Не читай packet.json: передай путь роли. Модель и effort берутся из `execution`; после изменения конфига обнови материалы через `sbox host install --target <хост>` и перезапусти сессию, если хост не подхватил их.

## Запуск роли

Для `kind: role` используй имя из `execution.agent` и сообщение `packet: <packetFile>`. Каждый запуск должен прочитать свежий пакет. Ключ повторного использования субагента: изменение + runner + agent + model + effort. Не продолжай агента другого изменения или с устаревшими настройками.

- **Claude Code:** запусти установленного агента через Agent; повторный запуск — через SendMessage. Агент пишет resultFile и возвращает его путь.
- **Codex:** запусти пользовательского агента по имени через доступный механизм субагентов (agent_type, если он поддерживается). Не подменяй его встроенным worker с унаследованной моделью. Если доступно продолжение завершённого агента — продолжи его, иначе создай нового с тем же типом. Агент возвращает полный Markdown и блок sbox-result в последнем сообщении. Сохрани ответ дословно в resultFile из brief: используй инструмент записи или безопасную передачу данных, без интерполяции ответа в shell-команду. Роли с read-only песочницей не должны запрашивать запись ради отчёта.

Дождись завершения роли. Не создавай отдельные пользовательские задачи вместо субагентов. Промежуточный статус, обрыв или пересказ ответа не являются отчётом.

Если текущий клиент Codex не позволяет выбрать установленного пользовательского агента, используй **headless-путь**: `sbox run --runner codex --change <id> --max-runs 1 --json`. Он сам запускает роль с нужными настройками и принимает ответ; повторно report не вызывай. Дождись завершения, покажи итог, снова запроси next. При ошибке запуска, недоступной модели или CLI остановись и покажи диагностику; не заменяй модель молча. Если результат остался в ожидании/ошибке, не запускай бесконечные повторы.

## Приём результата

После нативного субагента выполни `sbox report --change <id> --role <role> --runner <хост> --json`. Показанные в execution настройки — запрошенные, не доказательство фактического запуска: не заполняй --model/--session предположениями.

Покажи строку summary дословно и диагностики. Если отчёт отклонён, снова запроси next для свежих packetFile/resultFile и передай ошибки роли; максимум две попытки исправления, затем остановись с диагностикой. Не продолжай роль, если CLI уже принял блокер и назначил другой следующий шаг. Повторная сдача принятого ответа безопасна: alreadyApplied не создаёт новый запуск.

Повторяй next после принятых отчётов до gate, wait, deliver или done.

## Остальные шаги

- **gate:** покажи пути артефактов, conflicts и questions из CLI. Получи решение человека. «Да» → команда approve из ответа; замечания → reject с текстом. Ответы на вопросы передай через --answer. После решения снова next. Не утверждай гейт самостоятельно.
- **deliver:** покажи `sbox deliver --change <id> --check`. Запускай доставку только по просьбе пользователя; это архивирование, коммит, push и пул-реквест.
- **wait:** покажи статус и блокер, остановись. Продолжение выполняется через `sbox change resume` после разрешения причины; при parked нужен новый бюджет --returns.
- **done:** сообщи о завершении.

При просьбе остановить активный headless-запуск используй `sbox stop --change <id>`. При нативном запуске останови также субагента средствами хоста; не сдавай его незавершённый ответ. После утраты контекста восстанови состояние через CLI, а не по памяти о последнем сообщении.
