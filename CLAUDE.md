# Правила разработки @spec-box/sdd

Инструмент универсален и работает с несколькими хостами разработчика. Эти правила обязательны для любых правок.

- **Хосты равноправны.** Claude Code и Codex сегодня, другие потом. Возможность для одного хоста без покрытия остальных или явной записи в план (docs/design.md, раздел 15) не принимается.
- **Всё, что читают агенты и хосты, хранится как данные в `assets/`**: роли (`assets/roles`), схема артефактов (`assets/schema`), шаблоны, категории документации, скиллы (`assets/skills`). Тексты для агентов в коде адаптеров запрещены.
- **Скиллы: единый источник `assets/skills/<имя>.md`** с фронтматтером `name`, `description`, `metadata.roles`. При `sbox init --host` и `sbox host install` адаптер копирует файл без изменений в раскладку хоста (таблица `SKILL_LAYOUT` в `src/adapters/host/skills.ts`) и подключает ролям из `metadata.roles` средствами хоста. Проект может заменить скилл файлом `.sbox/skills/<имя>.md`.
- **Механизмы, а не знания о конкретном проекте.** Детерминированные помощники подсказывают, решают роли; проектные чеклисты живут в `.sbox/wiki` и ADR, а не в текстах ролей.
- **Тесты вместе с кодом**: vitest, сквозные проверки на фикстурах из `test/fixtures`; браузерные тесты пропускаются без браузера.
- **Версию в package.json и публикацию в npm меняет только владелец.**
- **docs/design.md — источник решений**: изменение поведения сопровождается правкой документа; тексты на русском.
- Сборка: `./node_modules/.bin/tsc -p tsconfig.json`; тесты: `./node_modules/.bin/vitest run`; CLI: `node bin/sbox.js`, `node bin/sbox-browser.js`.
