## Формат дельты спецификаций (адаптер spec-box)

Истина хранится в YAML-файлах spec-box: `feature`, `code`, `specs-unit` (группы утверждений `assert`). Одна группа соответствует требованию, одно утверждение соответствует сценарию, и на каждое утверждение приходится один автотест. Нормативный текст требования пишите полным предложением в названии группы (например, «Сессия завершается после 30 минут бездействия»), шаги GIVEN/WHEN/THEN пишите в `description` утверждения.

Дельта лежит в `specs/<code>.yml` папки изменения, по одному файлу на capability:

```yaml
code: checkout-page                 # обязательно; совпадает с code существующей фичи или задаёт новую
feature: Страница оформления заказа # обязательно только для новой фичи
description: Назначение фичи        # для новой фичи: 1–2 предложения
type: Functional                    # опционально
definitions:                        # опционально, атрибуты из .spec-box-meta.yml
  page: [checkout]

added:                              # новые группы или новые утверждения в существующей группе
  Пользователь может выбрать адрес доставки:
    - assert: При нажатии «Выбрать адрес» открывается диалог выбора адреса на карте
      description: |
        GIVEN пользователь на странице оформления
        WHEN нажимает «Выбрать адрес»
        THEN открывается диалог с картой и полем поиска

modified:                           # полная замена утверждений существующей группы
  Отображается сводка заказа:
    - assert: Отображается количество и общая стоимость товаров с учётом скидки

removed:                            # удаление группы целиком или отдельных утверждений
  Промокод применяется на странице корзины:
    reason: Промокод переносится на страницу оформления
    migration: Сценарии покрыты группой «Промокод применяется при оформлении»
  Блок рекомендаций:
    asserts: ["Отображается блок «С этим покупают»"]

renamed:
  - from: Старое название группы
    to: Новое название группы
```

Правила:
- `modified`, `removed`, `renamed` применимы только к группам, которые есть в истине (`sbox spec show <code> --json`).
- Для новой фичи допустима только секция `added`.
- В `modified` перечисляйте все утверждения группы целиком, а не только изменённые. Если группа одновременно переименована в `renamed`, в `modified` пишите её под новым названием.
- Утверждение формулируйте наблюдаемым поведением с точки зрения пользователя или внешнего контракта; одно утверждение проверяет одно поведение.
- Названия групп и утверждений попадают в имена тестов (`describe` и `it`), поэтому не используйте в них кавычки-ёлочки внутри кавычек и переносы строк.
