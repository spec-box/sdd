# sbox-wiki

Работает с project.wiki из .sbox/config.yaml. Для отдельной папки без SDD укажи `--dir <папка>`; пути считаются от `--cwd`. Используй `--json` для структурированного ответа, кода ошибки и revision.

- `sbox-wiki index --json`: карточки страниц с summary, read_when, source_roots и заголовками. Содержимое страниц в индекс не включается. Для большого wiki начни с поиска.
- `sbox-wiki search "задача" --path src/module --limit 5 --json`: результаты с причинами совпадения и фрагментом. Поиск лексический, попробуй другие термины при пустом результате. --path повышает приоритет страниц области, не ограничивает выдачу.
- `sbox-wiki get <id|путь.md> --json`: полный Markdown и revision. `--section <якорь>` читает раздел; для редактирования получи полную страницу.
- `sbox-wiki backlinks <id|путь.md> --json`: страницы, на которые повлияет удаление раздела или перенос.
- `sbox-wiki put <id|путь.md> --file <файл> --if-match <revision> --json`: сохранить полную страницу. При WIKI_CONFLICT перечитай её и перенеси свою правку в новую версию. Для создания: `put область/page.md --file <файл> --create`.
- `sbox-wiki validate --json`: метаданные, дубликаты id, отсутствующие страницы и разделы. Ссылки за пределы wiki считаются ошибкой, внешние URL не проверяются. В примерах кода ссылки не проверяются.

Пиши summary как краткое описание конкретного знания, read_when как ситуации, в которых оно помогает. Обновляй их вместе с содержимым. Метаданные составляются автором или агентом, CLI не генерирует их. Отсутствие диагностик не подтверждает истинность текста.

Сохраняй знания только в рамках полномочий текущей роли: наличие команды put не расширяет их. Markdown — источник истины; файлы можно редактировать напрямую. Кеш обновляется при изменениях файлов; `index --rebuild` восстанавливает его. put проверяет всю wiki до записи, включая входящие ссылки на изменяемые якоря. Для согласованной правки нескольких взаимосвязанных страниц отредактируй файлы и затем выполни validate.
