# Профили моделей в Agentic OpenSpec

Источник: https://sourcecraft.dev/deepsweet/agentic-openspec/, ревизия `caed7fc178996bb3cbf89c4c6e066728ad5bc40a`, просмотрено 2026-09-28. Исследованы исходники без запуска кода проекта.

Настройки хостов разнесены в `src/.agents/agents/claude`, `codex`, `cursor`; тексты ролей общие в `src/.agents/roles`. Варианты ролей называются planner/planner-pro, implementer/implementer-pro, reviewer/reviewer-pro. Claude задаёт model и effort в Markdown-фронтматтере, Codex — model и model_reasoning_effort в TOML. Оркестратор выбирает имя агента; для первоначального усиленного планирования предусмотрен пользовательский тег #pro, для реализации и ревью — оценка планировщика.

Повышение класса работы не обязательно меняет модель: в просмотренной версии Codex implementer и implementer-pro используют одну модель с medium/high. Это аргумент хранить пару model + effort вместе. У каждого хоста собственные пары; трехуровневого общего профиля в просмотренной реализации нет.

В @spec-box/sdd используем общие профили simple/medium/complex и отдельную таблицу пар для каждого раннера. Единственная функция выбора используется headless-циклом, пакетами ролей и генератором агентов Claude. Конкретные идентификаторы моделей из референса не переносились: сохранены исходные дефолты SDD, новые значения задаёт проект. Нативные агенты Codex теперь генерируются в .codex/agents; его headless-раннер использует ту же политику.
